## 先取得本场约束

复用用户已给资料，按任务补齐：店铺与账号资格、品类、直播时间及时区、团队、实际可售实物及证明、现有设备、物流模式与仓库、成本、价格和预算约束。缺少成本时先给测算字段，不自行指定起拍价、费率或补贴金额。内部期望价仅用于开拍前测算，不设为可拒绝成交的保留价。

优先交付下一场最需要的三项动作、排品表、单品脚本、邮费自检和复盘；用户只需其中一项时直接完成该项。

相关拍品的权限、允许类目、实物与链接、关键商品事实或履约条件未通过核验时，暂缓该拍品或玩法；其他已核验商品仍可继续准备。关键事实不完整的脚本保留占位符，标为待补齐草稿，不作为可直接上播稿。

## 从 0 到 1：课程十步与中控路径

第三篇给出的顺序为：**账号功能 → 设备场景 → 选品 → 预告 → 暖场 → 首拍 → 轮转 → 互动 → 收尾预告 → 订单履约复盘**。

| 环节 | 落地核对与完成证据 |
|---|---|
| 账号功能、设备场景 | 后台资格及功能截图；用现有设备试录声音、画面和商品演示，手机可开播，不强制使用 OBS 或采购其他设备 |
| 选品、预告 | 实物与链接一一核对；预告使用真实商品和明确的时间、时区 |
| 暖场、首拍、轮转、互动 | 彩排商品讲解、置顶和开拍；记录问题及切换时间，按实际反馈调整 |
| 收尾预告、履约复盘 | 下一场信息已确定才预告；核对已售、付款、库存与履约，保存本场事件记录 |

课程 2.4 的三种上架路径：

| 路径 | 课程用途与核实点 |
|---|---|
| 临时发品 | 便于快速测试；审核、复用及当前支持范围另核实 |
| 商家后台创建 | 便于长期商品管理；按当前界面核实必填信息与状态 |
| 批量上传 | 面向大量 SKU；PC 支持、格式与可用功能以当前后台为准 |

课程 2.5 的中控顺序：**添加已备商品 → 正确置顶 → 开拍前编辑当前可配置参数 → 开始拍卖 → 到已售商品核对销售和付款**。先用彩排验证链接、实物和操作者一致，不把历史截图当成当前按钮路径。

## 选品与可执行排品表

课程 3.2 的四角色为 Hook 引流、Star 爆款主力、Cash Cow 利润、Buzz 气氛；可简化为引流、主力、压轴三层。角色服务于本场目标，不代表商品自带利润或平台分类。用实际库存、可证明价值、展示效果、利润及物流风险挑选，再安排主题系列、搭配和价格梯度。

原文不同位置比例不一，不设全店固定配比。7.10 的混场试排示例为引流 20%、一口价承接 40%、利润 30%、形象 10%；仅在用户需要该例时注明课程示例，按本店目标重新分配并归一至 100%。

常规每件包含讲解、竞拍与切换约 3–5 分钟，是课程排期参考。先从总时长扣除暖场、互动及收尾，按彩排的完整单品用时估算件数，再为系统延时和异常留空间；不能用竞拍倒计时直接推算上货件数。

**新编模板：**

| 顺序／时段 | 实物编号／链接 | 角色／价值证据 | 内部价格测算／起拍价 | 时长／结束方式 | 运费／合单核验 | 负责人 |
|---|---|---|---|---|---|---|
| 〔待填〕 | 〔SKU、实物、链接〕 | 〔角色、材质或状态依据〕 | 〔成本口径、可接受结果、实际设置〕 | 〔后台配置、延时规则〕 | 〔模式、模板、核验结果〕 | 〔人〕 |

内部价格测算使用本店真实数据，见 [growth-review.md](growth-review.md)；不把课程案例或其他商家的成本、运费、费率、预算设为默认值。不要默认使用课程中的低价起拍例子，先看可能成交结果是否可承受。

## 单款五步：保留原名与顺序

下表时间为课程参考标注，不是平台硬性标准或当前后台倒计时。先确认系统步长、结束及延时方式；话术必须与实际配置一致。右列为新编话术占位符，仅填已核实事实。

| 课程步骤 | 课程时间参考 | 新编脚本框架 |
|---|---|---|
| 1. 商品展示 | 30–60 秒 | “这次是〔实物编号〕。这里看全貌和〔细节／瑕疵〕；〔价值表述〕的依据是〔材料〕。” |
| 2. 规则说明 | 10–15 秒 | “本轮起拍价为〔实际设置〕，系统步长是〔值〕，结束和延时方式为〔当前规则〕。” |
| 3. 启动竞价 | 0–15 秒 | “现在开始，请确认画面中的〔商品／规格〕与置顶链接一致。” |
| 4. 引导加价 | 15–60 秒 | “刚才问到〔真实问题〕，这里可以看到〔实物演示／有依据的回答〕。”自然回应，不施压或制造假竞争 |
| 5. 落槌成交 | 10 秒 | “本轮已按系统结果结束；我们核对〔已售记录／付款状态〕，接下来展示〔下一件〕。” |

不安排亲友或场控出价，不托价，不提供保留价机制。开拍后不修改起拍价、时长或结束方式，不人工延时，不因成交价低而取消。后台显示与口播不一致时保留记录并核实，不能靠口头改写结果。

## 三段人气与混场承接

- **开播前：**课程建议提前 24–48 小时按资源发布商品预览或 Event，标明时间及时区；这是排期参考，不要求固定内容数量或花费。
- **直播中：**回答真实问题，展示待拍清单和实物预告；互动不能保证平台推荐，不把课程中的倍数或增长百分比当效果承诺。
- **收播后：**用有权使用的片段制作切片，围绕已确定的固定场次做回访安排。生成安排不等于自动发群消息或开广告；赠品工具另核规则。

混场思路是拍卖聚人，再用独立一口价商品或符合条件的 Flash Sale 承接未中拍需求；套装或赠品增加连带是待验证的经营假设。先用“引流＋承接＋利润或形象”的小组合演练，再按证据扩展，不预设固定场长或观众人数。

拍卖链接与独立一口价库存分开核对。按一个拍卖链接对应一件明确实物备场；套组先核当前支持范围，并在开拍前明确全部内容、库存、链接及允许类目。不多链接出售同一实物、不把已成交物重拍、不制造虚假稀缺。随机盲盒、轮盘、Reserve Price、人工加价等原文提法转至合规核实，不直接启用或写成隐藏商品脚本。

## 邮费与合单自检

先确认物流模式、仓库、品类、运费模板及后台实际支持的合单功能。US 本土、跨境 POP 直邮、FBT 等条件不能混用，不将课中 4PL 或 Seller Shipping 的通用路径直接套给 POP。

测量真实首件、续件、地区差异、计费重和体积重，再比较后台可用的固定、件数或重量方案。透明展示运费，使其贴近真实履约成本，不能用高运费隐藏商品利润。

**新编核验表：**优先用结算预览或测试工具，不为验证而下会收费的真实订单；若必须真实交易，另按用户具体授权处理。

| 测试情景 | 记录内容／通过证据 |
|---|---|
| 1、3、5、10 件 | 商品合计、展示运费、可能包裹数与履约成本，保存预览结果 |
| 跨商品链接 | 是否实际合并计费、库存与订单映射是否正确 |
| 退款其中一件 | 运费及优惠如何重算、剩余订单如何履约；只使用可用的测试方式 |
| 偏远地区 | 地区附加费、可配送性与承诺是否一致 |
| 不同仓库或时限 | 拆包、合单限制、发货时限与包装要求 |
| 包装及物流状态 | 实际包裹尺寸重量、订单对应、物流更新与追踪记录 |

买家、订单、实际包裹分别统计；同买家可合单不表示一定只有一票。原文合单窗口存在 24 小时与 48–72 小时等冲突，不能选一个当通用规则，以当前后台和官方说明为准。

## 下一场复盘底稿

按实物或拍卖轮次记录：〔角色〕、〔完整用时及系统延时〕、〔成交与付款状态〕、〔承接商品表现〕、〔退款成熟度〕、〔运费收入与实际包裹成本〕、〔异常和证据时间点〕。

对齐数据口径后，区分已知事实、经营假设和待核实规则；选下一场优先三项动作，填写〔具体改变／负责人／完成证据／复查时点〕。不要以单场人气上涨确认互动有效，也不要把成交额等同净利润。
